# exec-proxy の失敗ポリシー

workflow script は決定論 script を直接実行できないので、`agents/` の dev-runner 系 subagent に `bin/` の bare 名を実行させ、
応答を verbatim で受ける（exec-proxy）。このファイルは proxy ごとに、何を失敗とみなし、どのポリシーで扱い、なぜそうするかの表だけを置く。

- 起動形（bare 名・`.git/config` を書かない・sandbox 内で動かす）と GitHub I/O の規範は `.claude/rules/dev-flow.md` の
  「exec-proxy（起動形の制約）」節が正
- harness の能力に依存する判断（exec-proxy の橋・CI polling の turn 会計・plugin の `bin/` PATH・長い `sleep`・
  `GIT_OPTIONAL_LOCKS=0`）は `capability-bound.md`
- どの agent が担うか・tools・maxTurns は `agents/*.md` の frontmatter（`_lib/agent-frontmatter.test.mjs` が pin）
- 呼び出し方・prompt・定数の値は表の 1 列目に挙げた script / 関数を読む。`bin/` の登録名は `tests/bin-wrappers.bats` が pin

本文のパスは `plugins/dev-flow/` を root とする plugin 相対パス（`.claude/rules/` と `tests/` は repo root）。1 列目の label は
`.claude/workflows/*.js` の `agent()` の label（`<i>` 等は実行時の値）で、`_lib/devflow-rules-hygiene.test.mjs` が実在を検査する。

## ポリシーの意味

- **fail-closed** — 失敗を「通さない」側に倒す（全 SEC seed を unchecked・HOLD・終端）。決定論 gate の入力不明を通過と同一視しない
- **fail-safe** — 安全側の既定（complex floor・HOLD・人間へのエスカレーション）に倒して続ける
- **fail-open** — 失敗を無視して続ける（警告 log・返り値で観測できる形にする）。gate の判定は変えない
